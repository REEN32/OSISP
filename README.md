# Лабораторная работа № 5: TCP-чат

Приложение написано на C++20 с использованием Winsock; проект открывается в Visual Studio из `LAB5.slnx`. В целях воспроизводимого тестирования имеется совместимая с POSIX реализация сетевых вызовов. По умолчанию адрес 127.0.0.1, порт 20027 (STUDENT_ID = 27), тайм-аут 30000 мс. Очереди находятся только в памяти и исчезают при завершении сервера.

## Запуск

В нескольких консолях запустить (путь к exe зависит от конфигурации Visual Studio):

```
LAB5.exe server --host 127.0.0.1 --port 20027 --timeout 30000
LAB5.exe client --host 127.0.0.1 --port 20027 --timeout 30000 --id alice
LAB5.exe client --host 127.0.0.1 --port 20027 --timeout 30000 --id bob
LAB5.exe client --host 127.0.0.1 --port 20027 --timeout 30000 --id carol
```

Клиент автоматически входит, принимает очередь и проверяет новые сообщения примерно раз в секунду. Команды: `SEND bob Текст сообщения`, `GET_PENDING`, `LOGOUT`; регистр команды не важен. `GET_PENDING` также позволяет проверить очередь вручную. Для завершения сервера в его консоль введите `stop`: активные соединения будут закрыты. Значение `--timeout` задаётся в миллисекундах и ограничивает ожидание во время передачи кадра и ответа; простой подключённого клиента между командами не приводит к отключению. Идентификаторы — латинские буквы, цифры, `_` и `-`, не более 32 символов. Текст не должен содержать табуляции.

## Протокол

Каждый кадр состоит из четырёхбайтовой длины в сетевом порядке и полезной нагрузки UTF-8 (1–65536 байт); поля разделены табуляцией. В каждом кадре первые поля — версия `1`, тип и десятичный идентификатор запроса. Запросы: `LOGIN id`, `SEND recipient text`, `GET_PENDING`, `LOGOUT`. Ответы: `OK`, `ERROR`, `MESSAGE id sender text`, `END`. Каждое MESSAGE подтверждается кадром `ACK` с идентификатором запроса и сообщения. После подтверждения сервер удаляет запись. Для SEND при 20 ожидающих сообщениях сервер возвращает `ERROR QUEUE_FULL`. Одновременный вход под одним идентификатором запрещён. В случае обрыва до приёма ACK сообщение остаётся в очереди и может быть получено повторно; строгая доставка ровно один раз при сбоях не гарантируется. Сообщения, отправленные подключённому пользователю, также помещаются в очередь и забираются командой GET_PENDING.

## Эксперименты

В macOS/Linux: `c++ -std=c++20 -pthread LAB5/LAB5.cpp -o /tmp/lab5`, затем `python3 experiments/test_chat.py --exe /tmp/lab5`. В Windows: `python experiments/test_chat.py --exe path/to/LAB5.exe`. Параметры `--host`, `--port`, `--timeout`, `--counts` и `--repeats` доступны без изменения кода. Скрипт использует три одновременных соединения, отключает Bob, отправляет 5, 20 или 21 сообщение, проверяет FIFO, повторное получение и переполнение. Результаты: `experiments/results.csv`; `python experiments/plots.py` создаёт графики (нужна библиотека Pillow). Редактируемое описание диаграммы: `experiments/sequence.mmd` (Mermaid).
