# Проектирование варианта 4

Один процесс, N рабочих потоков философов и главный поток. Нумерация 0..N−1.
Левая вилка i, правая (i+1)%N. Чётный философ берёт левую, затем правую;
нечётный — правую, затем левую. Каждой вилке соответствует отдельный Windows Mutex.
Число вилок равно числу философов и независимо не меняется, поскольку это свойство модели.
Основной режим asymmetric; ordered — контрольная конфигурация с общим порядком вилок.

Общие данные: владельцы вилок, признаки EATING и журнал под отдельными короткими
CRITICAL_SECTION. Монитор не выдаёт разрешения на еду: исключение обеспечивают Mutex.
Нельзя ждать вилку, удерживая блокировку монитора или журнала.
Собственная статистика потока читается главным потоком только после join.
START/STOP/DONE — ручные Event. Остановка кооперативная, захваченные вилки освобождает RAII.

Номинально 5 философов, 100 циклов, THINK=2 мс, EAT=2 мс; отдельно 7 и THINK=15.
Индивидуально ID=027, SEED=3619, CYCLES=235. JITTER=1 мс, фиксированный
генератор каждого потока определяет воспроизводимые задержки, но не планирование ОС.
Предусмотрены дедлайн, таймаут пары вилок, подробный журнал и JSON.

Доказательство: зависимости между вилками задаются первым и вторым захватами.
В графе ресурсов рёбра i→i+1 для чётного i и i+1→i для нечётного i.
Единственный возможный простой цикл в неориентированном кольце при N≥3
потребовал бы одинаковой ориентации всех рёбер. При N≥3 присутствуют обе
ориентации, поэтому ориентированного цикла нет. Для N=2 оба участника берут
вилку 0 первой. Значит, круговое ожидание невозможно. Отсутствие голодания
не следует из этого: Windows Mutex не гарантирует FIFO.

Замеры portable не подтверждают поведение Windows API и явно помечаются.
Необходимо отдельно провести Windows-серию; результаты нельзя подменять.
