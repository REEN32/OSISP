# Подготовка к защите

1. **Что защищает Mutex?** Одну вилку. Захват каждой вилки атомарен; чтение флага без Mutex таким свойством не обладает.
2. **Почему одной вилки недостаточно?** Еда требует двух разных ресурсов. Условие проверяется перед входом в EATING.
3. **Почему не возникает deadlock?** Условия кругового ожидания нет: чётные и нечётные берут вилки в противоположных направлениях. В кольце не может образоваться направленный цикл. Объясните отдельно N=2 и нечётные N=5/7.
4. **Разве тайм-аут доказывает отсутствие deadlock?** Нет. Он ограничивает ожидание одной попытки и помогает обнаружить ошибку, но доказательство основано на графе зависимостей.
5. **Возможно ли голодание?** Windows Mutex не гарантирует FIFO. Алгоритм не доказывает ограниченного ожидания. Завершение всех потоков в серии — экспериментальный факт.
6. **Почему Sleep недостаточно?** Задержка не предоставляет исключительное владение. Здесь ресурсы синхронизированы Mutex, а задержки лишь моделируют действия.
7. **Почему вместо Sleep используется ожидание STOP с тайм-аутом?** Так модельная задержка прерывается при отмене.
8. **Для чего критические секции?** Только для служебного журнала и наблюдения инвариантов. Они не заменяют Mutex вилок и не удерживаются во время ожидания вилки.
9. **Можно ли использовать CRITICAL_SECTION между процессами?** Нет. Для независимых процессов нужны подходящие разделяемые данные и именованные Mutex/Event/Semaphore.
10. **Что такое WAIT_ABANDONED?** Предыдущий владелец завершился без освобождения. Новый поток уже получил Mutex, но данные ненадёжны. Здесь Mutex освобождается и эксперимент прерывается с ошибкой.
11. **Как выполняется остановка?** Главный ставит STOP, блокирующие ожидания возвращаются, RAII освобождает вилки, последний работник ставит DONE, главный join-ит потоки, затем объекты уничтожаются.
12. **Почему N=7 не даёт гарантированно ускорения в 7/5?** Добавляются и ресурсы, и нагрузка; одновременная еда ограничена соседством, плюс накладные расходы и квантование таймеров.
13. **Что воспроизводится seed?** Значения псевдослучайных задержек при той же последовательности обращений. Не расписание потоков; при ретраях последовательность обращений тоже меняется.
14. **Как вычислены индивидуальные значения?** 027 — десятичное 27, SEED=1000+27×97=3619; C=100+27×5=235. Это число циклов на каждого философа.
15. **Какие данные настоящие?** Все JSON в data/portable получены программой на macOS, не Windows. Для Windows требуются запуск scripts/windows.ps1 и новый отчёт. Не заявляйте об испытаниях, которые не выполнены.
16. **Что делает ordered?** У всех участников первая вилка имеет меньший номер. Это другая корректная стратегия на том же Mutex для сравнения порядка захвата.
17. **Зачем два показателя ожидания?** Среднее для завершённых циклов характеризует успешное получение двух ресурсов; максимальное показывает длинные задержки. Число тайм-аутов относится к попыткам, а не потерянным операциям.
18. **Что считается операцией?** Один полностью законченный приём пищи. Прерванная дедлайном еда не засчитывается.

Перед защитой заполните титульный лист, выполните Windows-серию, проверьте нулевые нарушения, опубликуйте репозиторий с доступом преподавателю. Откройте исходный код, графики и Git-историю. Не забудьте указать реальное использование ИИ, описанное в приложении А.
